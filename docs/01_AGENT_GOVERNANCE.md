# حاکمیت و قواعد همکاری عامل

## مخازن
- مخزن فعال: `akhlaghimhd/hamarehOffice`؛ شاخه جاری `main`.
- مخزن قبلی: `akhlaghimhd/hamarehCRM`، شاخه `feature/filament5-upgrade`؛ فقط خواندنی.
- شاخه `develop` مخزن قدیمی فقط خواندنی است و روی `main` مخزن قدیمی بدون اجازه صریح چیزی نوشته نمی‌شود.
- ابتدای هر کار branch، HEAD، remote و working tree بررسی شود.

## حفاظت Git
`git clean`، `reset --hard`، حذف تغییرات محلی، force push و عملیات مخرب بدون اجازه صریح ممنوع است. قبل از pull/merge/switch وضعیت working tree بررسی شود. secrets و `.env` هرگز commit نشوند. پیش از ویرایش فایل remote، محتوای فعلی و SHA تازه خوانده شود. Commit انگلیسی و Conventional Commits باشد.

## معماری
- جداسازی عملیاتی فقط با `company_id`؛ `tenant_id` ممنوع.
- Identity/Auth/Session/Company Membership/Role/Permission یکپارچه؛ سیستم موازی نساز.
- Laravel مالک منطق دامنه و مجوز نهایی است؛ Vue لایه ارائه است.
- Filament در پروژه جدید نصب یا استفاده نشود.
- Inertia یا Blade + Vue/API هنوز تصمیم نهایی نیست؛ spike فنی و آزمون deploy لازم است.
- کاتالوگ، قیمت، قواعد و Workflow تا حد ممکن data-driven و versioned باشند.
- Snapshot سفارش تأییدشده immutable باشد.
- موجودی event-based و قابل ردیابی؛ جلد و داخله مستقل.
- DB فقط با Migration تغییر کند.
- UI فارسی، RTL و mobile-first؛ اعداد فارسی در UI و تاریخ شمسی در UI.
- مقصد هاست اشتراکی؛ Node فقط build-time.

## گردش کار
1. وضعیت Git و محیط واقعی را بررسی کن.
2. اسناد و کد واقعی مرتبط را بخوان.
3. نیازمندی، تصمیم مصوب، پیاده‌سازی قدیمی، تست قدیمی، prototype و قابلیت جدید را جدا ثبت کن.
4. پیش از تغییر محدوده و راهکار را روشن کن؛ فقط حداقل تغییر ضروری.
5. برای منطق کسب‌وکار تست اجرا یا پیشنهاد کن.
6. diff و وضعیت نهایی را بررسی کن.
7. گزارش فارسی شامل نتیجه، فایل‌ها، Commit، تست‌ها و کارهای باز بده.
8. هیچ موفقیت یا تکمیلی بدون شواهد اعلام نکن.

مالک تصمیم‌گیر نهایی است. کارهای خرد فنی را مستقل انجام بده؛ تغییرات پرریسک یا برگشت‌ناپذیر نیازمند اجازه‌اند.
