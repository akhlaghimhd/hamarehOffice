# تصمیم مهاجرت رابط کاربری

**وضعیت:** مصوب — 2026-11-21  
**مخزن:** `akhlaghimhd/hamarehOffice` | **شاخه:** `main`

## تصمیم مصوب

پشته UI رسمی پروژه:

| لایه | انتخاب |
|------|--------|
| Backend | Laravel |
| اتصال frontend | **Inertia** |
| UI framework | **Vue 3** |
| استایل | **Tailwind CSS** |
| سیستم کامپوننت | **shadcn-vue** |
| Database | MariaDB |
| استقرار | هاست اشتراکی؛ Node فقط build-time؛ SSR خاموش |

Filament در پروژه جدید مبنای UI نیست و **نباید نصب شود**.

## معیارهای تصمیم (اولویت مالک)

1. آزادی کامل UI و موبایل (حتی اگر کمی بیشتر کد نوشته شود)
2. ظاهر زیبا و مدرن؛ پرهیز از نوشتن UI از صفر
3. انعطاف برای سناریوهای دلخواه بدون قوانین خشک پنل‌ساز
4. موبایل و دسکتاپ عالی؛ حس شبه اپ
5. اجرا روی هاست اشتراکی بدون Node runtime دائمی

## چرا این پشته

- **shadcn-vue:** کامپوننت‌ها در اختیار پروژه کپی/نصب می‌شوند؛ مالکیت کد و آزادی سفارشی‌سازی بالا؛ ظاهر مدرن.
- **Tailwind:** کنترل کامل ظاهر و mobile-first.
- **Inertia:** یکپارچگی با Route/Controller/Session/CSRF لاراول؛ حس SPA بدون API موازی در فاز اول.
- **بدون Filament:** رفع محدودیت ظاهر و قوانین خشک پنل‌ساز.

## اصول انتقال و پیاده‌سازی

- منطق دامنه و مجوز فقط در Laravel (Action/Service/Domain/Policy).
- Vue فقط لایه ارائه و تعامل.
- هویت، نشست، عضویت شرکت، نقش و مجوز واحد؛ سیستم موازی ممنوع.
- انتقال کورکورانه کد یا schema قدیمی ممنوع.
- ابتدا vertical slice محدود (ورود، انتخاب شرکت، مجوز، فهرست/جزئیات و یک عملیات نمونه) و deploy روی محیط هم‌ارز هاست؛ سپس تعمیم.

## ممنوعیت

- نصب یا استفاده از Filament
- login / role / permission موازی
- منطق حیاتی کسب‌وکار فقط در Vue
- Node runtime دائمی روی هاست
- SSR اجباری در فاز اول
- فرض این‌که prototype قدیمی Blade/Vue/fetch همان Inertia است
